# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-08-31 | Separate git repo per portfolio project (`docmind`), not a monorepo | A recruiter should land on a README that is only about this project |
| 2026-08-31 | `uv` for dependency + Python version management (`.python-version` = 3.12) | 10-100x faster than pip, one lockfile, and it downloads the exact Python the brief asks for even though the laptop has 3.13 |
| 2026-08-31 | `ruff` for lint + format (rules E, W, F, I, UP, B) | One fast tool replaces flake8 + isort + black; same config runs locally and in CI |
| 2026-08-31 | `hatchling` build backend, `pyproject.toml` only | Modern standard (PEP 621), no setup.py; enough for a package that is deployed, not published |
| 2026-08-31 | `pgvector/pgvector:pg16` Docker image for the database | Official Postgres 16 with the extension already compiled; one `docker compose up` and vector search works |
| 2026-08-31 | All configuration through one `pydantic-settings` `Settings` class (`docmind/config.py`) | Typed, validated (`LLM_BACKEND=openai` fails fast), documented in one place; no scattered `os.environ` reads |
| 2026-08-31 | `postgresql+psycopg://` (psycopg 3) driver | Modern, async-capable, maintained; psycopg2 is legacy |
| 2026-08-31 | SQLAlchemy 2 + Alembic for tables and migrations; `pgvector` Python package for the `Vector` column type | Tables as typed Python classes; migrations replay the same schema steps on laptop, CI and cloud so they never drift |
| 2026-08-31 | `pymupdf` for PDF text extraction; `langdetect` for per-document language | pymupdf is fast, keeps reading order and page numbers, no system deps; langdetect is tiny and good enough for de/fr/en/it at document level |
| 2026-08-31 | Microsoft Presidio for PII; start with pattern recognizers only (IBAN, email, phone), add spaCy-based name detection as a separate step | Pattern rules need no model download and are deterministic; name detection needs ~500 MB models per language and deserves its own evaluation |
| 2026-08-31 | spaCy `xx_ent_wiki_sm` (multilingual, 10 MB) for name detection in all four languages | One small model instead of three ~500 MB per-language models; enough to demonstrate the mechanism, swappable via one config dict; accuracy is a documented experiment for later |
| 2026-08-31 | `tiktoken` (cl100k_base) to count tokens in the chunker | Fast, tiny, no model download; bge-m3 uses a different tokenizer but sizes are within ~15 %, and 300-800 is far below its 8192 limit — verify as an experiment in M3 |
| 2026-09-01 | One `Embedder` protocol with `LocalEmbedder` (bge-m3), `AzureEmbedder` (text-embedding-3-large at 1024 dims) and `FakeEmbedder` (hash-based) | Same 1024-wide column serves both real backends, so switching is a config flag, not a migration; the fake keeps tests offline and fast |
| 2026-09-01 | Every embedding is normalised to unit length before storage | Cosine similarity then equals a dot product; pgvector `<=>` works identically for every backend and a future HNSW index can use `vector_cosine_ops` |
| 2026-09-01 | Model loading is lazy (first `embed()` call), never at import | The API, tests and CLI help can start in milliseconds; only the ingest run pays the ~2 GB download / ~10 s load |
| 2026-09-01 | Ingest = pure `prepare_document()` (redact + chunk) + `ingest_file()` that talks to the DB; duplicates detected by sha256; one bad PDF is reported, never aborts the batch | The pure part is unit-tested without Postgres; re-running the CLI is idempotent; a 400-page annual report failing must not lose the other nine documents |
| 2026-09-01 | PII redaction runs per page, before chunking | Placeholders then never straddle a chunk boundary and no raw personal data ever reaches the chunker, the embedder or the database |
| 2026-09-01 | Demo corpus = 13 public PDFs (FINMA circulars 2023/1 + 2026/1 in DE/FR/EN, 4 insurer AVB in DE/FR, 2 annual reports EN) fetched by `scripts/download_corpus.py` | Same circular in three languages gives a clean cross-lingual retrieval test; nothing is committed, the script re-creates `data/raw/` |
| 2026-09-01 | Full-text side = Postgres `tsvector` generated column (stemmer chosen per chunk language) + GIN index, ranked with `ts_rank_cd`; no separate search engine | Zero extra infrastructure; Postgres keeps the column in sync itself; per-language stemming (german/french/italian/english) is what makes "Schäden" match "Schaden" |
| 2026-09-01 | Vector side = pgvector cosine distance with an HNSW index (`m=16, ef_construction=64`) | HNSW gives millisecond approximate search and needs no rebuild when rows are added (IVFFlat does); cosine matches the normalised embeddings |
| 2026-09-01 | Hybrid = Reciprocal Rank Fusion (K=60) over the two ranked lists, with a `mode` switch hybrid/vector/keyword | RRF merges by rank, so incompatible score scales (cosine vs ts_rank) never need calibration; the switch makes "hybrid vs vector-only" a one-flag experiment in M3 |
| 2026-09-01 | `torch` pinned to the CUDA 12.8 index on Windows (dev laptop, RTX 3050) and to the CPU index on Linux (CI, containers) | CPU embedding ran at ~1.6 s/chunk (≈1.5 h per full ingest), too slow to iterate on chunk-size experiments; Linux CPU wheels keep CI/Docker images small |
| 2026-09-01 | Reranker = `BAAI/bge-reranker-v2-m3` cross-encoder on the top-20 fused candidates, behind a `Reranker` protocol with a `NoopReranker` (`RERANKER_ENABLED=false`) | A cross-encoder reads question and chunk together and is far more precise than either retriever; running it only on 20 candidates keeps it under ~0.5 s on GPU; the no-op makes "reranker on/off" a one-flag experiment |
| 2026-09-01 | LLM backends (Azure OpenAI, Anthropic, Ollama) behind one `LLM.complete(system, user)` protocol returning text + tokens + cost + latency | Every answer carries its own cost and latency, so the README numbers come from the code, not from a spreadsheet; the switch is `LLM_BACKEND` |
| 2026-09-01 | Prompt gives the model numbered sources and demands `[n]` after every factual sentence; numbers are mapped back to `(file, page, passage)` in code | Small local models reproduce `[2]` reliably but garble file names; mapping in code guarantees a citation can only point to a retrieved chunk |
| 2026-09-01 | `answer_question()` takes embedder, reranker and LLM as parameters; FastAPI builds them once at startup, tests inject fakes | Dependency injection keeps the API test offline and lets the eval harness swap one component per experiment |
| 2026-09-01 | Eval metrics implemented natively (recall@k, MRR, citation precision/coverage, LLM-judge faithfulness + correctness) instead of importing RAGAS | RAGAS drags in LangChain and needs an OpenAI-style judge; our judge runs through the same `LLM` protocol, so the eval works with Ollama offline. Metric definitions follow RAGAS (faithfulness = supported statements / all statements) |
| 2026-09-01 | Page match tolerance ±1 in recall@k and citation precision | A chunk is cited by the page it starts on and may run onto the next page; without tolerance, correct answers are scored as misses |
| 2026-09-01 | Keyword query terms are OR-ed (`plainto_tsquery` output with `&` swapped for `\|`), not AND-ed | `websearch_to_tsquery` demands every word, so a natural question ("Wie lang ist die Kündigungsfrist?") matched nothing unless a chunk contained "lang" too; OR + `ts_rank_cd` still ranks chunks with more matching terms first |
| 2026-09-01 | `audit_log` table written by the API on every `/ask` (username, question, retrieved + cited chunk ids, model, tokens, cost, latency, status) | The compliance trail FINMA-regulated users expect: any answer can be reproduced and reviewed later; kept in Postgres next to the data, no extra system |
| 2026-09-01 | HTTP Basic auth on the API, enabled only when `BASIC_AUTH_USER/PASSWORD` are set; the username lands in the audit row | Simplest thing that gives the demo deployment a login and a per-user trail; a real deployment would swap this dependency for OIDC/SSO |
| 2026-09-01 | Name detection switched from the multilingual `xx_ent_wiki_sm` to one small per-language spaCy model (de/fr/en/it `*_sm`), plus a "looks like a name" filter (2-4 Title-Case tokens, no digits) before a PERSON span is redacted | Measured on the corpus: the xx model marked 1105 of 1753 chunks (63 %) as containing a person — "Number of shares", "Schadenfalls", "Cash" — which would have poisoned retrieval and answers. Precision over recall is the right trade for regulatory documents; single surnames are a documented miss |
| 2026-09-01 | Embedder and reranker load on CUDA in float16 when a GPU is present | Halves VRAM (≈1.1 GB each) so bge-m3, the reranker and a 7B Ollama model can share a 6 GB laptop GPU; CPU float32 remains the fallback (CI, containers) |
| 2026-09-01 | Golden set = 96 questions (45 DE / 32 EN / 19 FR; 70 fact, 12 cross-lingual, 6 multi-doc, 8 unanswerable), each with the exact evidence sentence and PDF page index; authored per document group by Claude sub-agents and machine-checked that the evidence appears on the cited page | Page-verified evidence makes recall@k trustworthy; the four categories map to the four failure modes a reviewer cares about (wrong page, wrong language, one-document tunnel vision, hallucinating when the answer is absent) |
| 2026-09-01 | Observability = Langfuse **v2** self-hosted in the compose `observability` profile (single Postgres, headless-initialised keys) with the `langfuse<3` SDK; tracer is a no-op when keys are empty | Langfuse v3 needs ClickHouse + Redis + MinIO — too heavy for a laptop demo; the v2 image needs only Postgres and its `LANGFUSE_INIT_*` variables create the project and API keys without clicking through a UI. Verified: a trace with retrieval/rerank/generation spans round-trips through the public API |
| 2026-09-01 | New eval metric `context_hit` / `context_mrr`: recall and MRR scored on the k chunks handed to the LLM *after* reranking, next to the existing recall@k / MRR which score the fused candidate list *before* reranking | The first 20-question ablation showed `--no-rerank` with recall@5 and MRR identical to the baseline — not because the reranker does nothing, but because recall@k was measured before it runs. Both views are kept: recall@k answers "can the retrievers find the page at all?", context hit answers "does the LLM actually see it?" |
| 2026-09-01 | Abstention ("not in the documents") is detected with multilingual regex patterns (`metrics.is_abstention`) instead of four exact sentences; existing reports can be re-scored offline with `scripts/resummarise.py --rescore-abstention` | The first full run showed 0 % abstention although the 7B model had declined 5 of 8 unanswerable questions — it paraphrases the fixed sentence the prompt asks for ("wird in den Quellen nicht erwähnt", "do not contain information about"). A scoring bug, not a system failure; re-scoring stored answers is cheaper and more honest than hiding the run |
| 2026-09-01 | Latency statistics exclude questions whose wall-clock exceeded 600 s, and the excluded ids are written into the report's `config.latency_outliers_excluded` | The laptop went into standby mid-run (one question "took" 84 min); a mean latency of 60 s would be nonsense, silently editing the number would be worse. `scripts/keep_awake.ps1` now holds the system awake during long runs |
| 2026-09-01 | Defaults stay at hybrid retrieval, 20 candidates per retriever, reranker on, k = 5 chunks — confirmed by the full 96-question ablation matrix | Measured: hybrid 82 % recall@5 vs vector-only 81 % vs keyword-only 70 %; reranker lifts context hit@k from 82 % to 94 %; 40 candidates add 0.6 s for no gain after reranking; k = 3 loses 3 points of correctness. The vector-vs-hybrid gap is much smaller than the 20-question smoke set suggested (20 points) — decisions are taken on the full set only |
| 2026-09-02 | Chat-style web UI as one static HTML file (static/index.html) served by FastAPI, plus `GET /documents` for the sidebar library; citation chips `[n]` jump to source cards showing filename + page | A recruiter demo needs to look real; one file with no JS build step keeps 'API is the product' true. Same date: fixed the test fixture cleanup pattern (`test-rag-%` never matched `test-rag.pdf`), which had been leaking test documents into the database |
| 2026-09-02 | `GET /audit` endpoint (newest first, limit capped at 100, behind the same basic auth as `/ask`) + an 'Audit history' drawer in the web UI | An auditor should not need database access to see the compliance trail; the drawer makes the audit_log table visible in one click and demos well |
